# 机器学习滚动调参

只处理开发期调参。最终样本外验收、自动冠军选择和生产配置冻结不属于本 Skill。

先完整读取 [实验与数据契约](references/study-contract.md)，再生成计划或执行实验。

## 1. 适配目标仓库

先读取目标仓库指令、README、配置、数据字典、训练入口、预测入口、正式回测入口、测试和历史产物，建立执行映射：

- 数据覆盖、频率、交易日历、时区和可获得时间；
- 特征截止、标签区间、信号时点、成交时点及成本口径；
- 模型入口、参数来源、随机源和早停实现；
- 预测、Top-N 选股、持仓和成交规则的真实代码路径；
- 单次训练、预测和回测的命令、输入及输出。

只复用目标仓库已有实现。允许编写隔离的参数适配器和结果转换器；禁止在 Skill 中新建替代训练器、标签器、组合构建器或回测框架。找不到安全入口时停止对应实验并说明缺口。

## 2. 先确认时间和因果契约

根据数据实际覆盖提出开发期方案。默认候选验证年为 2017、2018、2019，但必须让用户确认；数据不支持时不得强行套用或自行替换年份。

逐项确认：

1. 开发验证区间；
2. 候选训练窗口及单位；
3. 标签持有期、purge 和 embargo；
4. 数据频率、交易日历和每个区间的可用样本数；
5. 开发期结束边界。

每个训练窗口必须完整落在可用数据内，严格结束在对应验证期之前。`purge_observations` 不得小于 `label_horizon_observations`。窗口不可行时直接失败；不得缩短窗口、切换为 expanding、跳过早期 fold 或借用开发期结束后的数据。

## 3. 区分固定项与搜索项

逐项询问用户哪些维度固定、哪些进入搜索：

- 训练窗口；
- 模型族和模型超参数；
- 显式命名的因子集合；
- 标签；
- 选股规则，包括 Top1/Top-N；
- 持仓规则；
- 成交规则；
- 其他会改变预测或回测结果的业务参数。

因子组合必须由用户显式提供，不自动生成因子全子集。随机种子是重复稳定性维度，不是可按表现挑选的超参数。

不同模型使用独立 `model_spaces`。先在每个模型空间内部展开其超参数，再把所得模型配方与训练窗口及业务维度做笛卡尔积；禁止在不兼容模型之间交叉参数。

使用 XGBRanker 时，先读取 [XGBRanker 参数空间](references/xgbranker-parameter-space.md)，按 Top1 目标区分固定参数、第一轮搜索参数和排序专属参数。

早停规则必须预先固定。若早停读取外层验证期，必须把规则和每次实际迭代数写入结果；不得在结果出现后修改早停规则。

## 4. 生成并确认完整计划

把配置写成契约规定的 `study_config.json`，运行：

```bash
python3 scripts/build_tuning_plan.py \
  --config study_config.json \
  --output-dir runs/tuning-plan
```

向用户展示：候选数、验证期数、seed 数、总 trial 数、各活动维度基数和估计资源需求。始终全量枚举，不提供随机搜索、贝叶斯优化、Successive Halving、提前淘汰或隐式剪枝。资源不足时要求用户缩小候选空间并重新生成完整计划。

相同候选在所有验证期保持完全相同的参数、因子、标签及交易规则；只有训练样本和重新拟合后的模型权重随 fold 改变。

## 5. 执行目标仓库实验

逐条读取 `trial_plan.jsonl`，调用目标仓库的真实入口。每个 trial 使用隔离输出目录，并记录：

- `trial_id`、`candidate_id`、`validation_id` 和 seed；
- 代码版本、配置哈希、命令和产物路径；
- 完成或失败状态、错误原因；
- 所有预注册指标；
- 使用早停时的实际迭代数。

将结果转换为契约规定的长表 CSV。不得只保留成功 trial、最佳 seed、最佳年份或表现较好的指标。

## 6. 汇总但不代替用户决策

运行：

```bash
python3 scripts/summarize_tuning_results.py \
  --plan-dir runs/tuning-plan \
  --results tuning_results.csv \
  --output-dir runs/tuning-summary
```

汇总器必须核对完整试验分母，输出逐验证期表现、跨期均值/中位数/最差期/标准差、各指标独立排名、完整性诊断和 Pareto 候选。失败和缺失 trial 保留在分母中；不完整候选不得进入排名或 Pareto 集。

报告只提供人工决策材料，不生成综合分、不宣布唯一最优、不输出推荐冠军，也不冻结配置。若用户之后要做最终样本外验收或正式冻结，应转入独立任务并使用未被本研究读取的数据。

## 边界

- 只读取和评价开发验证区间，不接受计划外 validation 或 trial。
- 不根据结果改变候选空间、指标方向、seed 集或早停规则。
- 不把开发期滚动验证称为最终样本外。
- 不以脚本成功运行替代目标仓库真实训练、预测和交易回测证据。
