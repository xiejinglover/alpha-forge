## 1. 时间配置

`study.json` 使用 ISO 日期：

```json
{
  "development": {"start": "2023-01-01", "end": "2025-12-31"},
  "holdout": {
    "start": "2026-01-01",
    "end": "2026-07-20",
    "consumed_for_selection": false
  }
}
```

两个区间必须完整、互斥且开发期早于留出集。`consumed_for_selection=true` 时仍可生成诊断结果，但不得把结果表述为独立留出确认。

## 2. 候选评分

长表 CSV 必须包含：

| 字段 | 说明 |
|---|---|
| `candidate_id` | 稳定且唯一的候选标识 |
| `metric` | 指标名称 |
| `score` | 开发期评分；必须可解析为数值 |

同一 `candidate_id + metric` 只能有一行。评分 CSV 只允许承载开发期汇总结果。指标方向通过 N 选优命令的 `--direction max|min` 冻结。

## 3. 候选收益

内置评分脚本的输入 CSV 必须包含：

| 字段 | 说明 |
|---|---|
| `candidate_id` | 候选标识 |
| `date` | ISO 日期 |
| `net_return` | 已按统一执行和成本口径计算的单期净收益 |

每个 `candidate_id + date` 只能有一行。脚本只读取开发期范围，拒绝其中夹带的非有限收益。

内置指标：

- `sharpe`：单期均值除以样本标准差，再乘 `sqrt(annualization)`；默认年化因子 252、单期无风险收益 0。
- `calmar`：按完整开发期复利计算年化收益，再除以最大回撤绝对值。
- `positive_month_rate`：先按自然月复利，再计算月收益严格大于 0 的月份占比。

标准差为零、最大回撤为零或观察不足时输出空评分，使该候选不能在对应指标中获胜。

## 4. 开发期与留出期多标的信号

信号 CSV 必须包含：

| 字段 | 说明 |
|---|---|
| `rebalance_date` | 调仓日，ISO 日期 |
| `candidate_id` | 候选策略标识 |
| `asset_id` | 当日由原策略选出的一个股票或 ETF 标识 |

同一策略在同一调仓日可以有多行，以保留原策略的 Top1、Top3、Top5 或其他选标数量；同一 `rebalance_date + candidate_id + asset_id` 只能出现一次。

开发期去相关输入必须只包含开发期数据。所有参与去相关的策略必须拥有完全相同的开发期调仓日历，并在同一调仓日选出相同数量 K 的不同标的。两策略当日相似度为选标交集数量除以 K，跨全部开发期调仓日取平均；平均相似度严格大于 0.6 时删除后排序策略。

留出期投票输入只读取留出期数据。最终成员在某调仓日缺少全部信号时，记录到诊断产物，不为其补票。

每个信号标的获得一张完整成员票，不在策略内部平分。若成员胜出 5 次并在调仓日输出 4 只标的，这 4 只标的在 `slot_weighted` 分支各得 5 票，在 `unique_equal` 分支各得 1 票。

## 5. 选择、去相关与投票产物

选择阶段输出：

- `groups.csv`：每场抽到的全部候选；
- `winners.csv`：每场状态和唯一赢家；
- `members.csv`：每个 N 的唯一赢家、当前指标分数、胜出次数和原始席位权重；
- `selection_manifest.json`：时间边界、默认参数、实际参数、覆盖情况、输入与产物哈希。

去相关阶段输出：

- `similarities.csv`：每个 N 的策略对、共同调仓日数和平均选标重合率；
- `decorrelation_trace.csv`：稳定处理顺序、最大相似度、阻断策略及保留/删除决定；
- `decorrelated_members.csv`：后续流程唯一认可的新策略池、原胜出次数和新池席位权重；
- `decorrelation_summary.csv`：每个 N 去相关前后成员与席位变化；
- `decorrelation_manifest.json`：阈值、上游冻结哈希、开发期信号哈希及产物哈希。

投票阶段输出：

- `member_votes.csv`：每个赢家的全部原生选标及每个标的获得的完整投票权；
- `missing_signals.csv`：在调仓日缺少全部标的信号的赢家；
- `asset_votes.csv`：两种成员投票方式下的完整标的票数与排名；
- `target_weights.csv`：`all` 和各 Top-K 的调仓目标权重；
- `portfolio_manifest.json` 和 `summary.md`：冻结来源、输入哈希和配置汇总。

## 6. 时间隔离和异常处理

- 在选择阶段不得读取留出期信号或回测结果。
- 去相关只能读取开发期选标信号，禁止使用净值、收益或留出期信号。
- 在投票前校验去相关清单及关键产物哈希；原始选择清单不能直接投票。
- 不覆盖非空输出目录。
- 候选数小于 N 时失败，不改变 N 的含义。
- 全组评分均无效时记录 `invalid_group`，不重抽、不回退。
- 开发期调仓日历缺失、重复标的或同日选标数量不一致时停止去相关。
- 去相关按当前指标优先级执行，平均选标重合率严格大于 0.6 时删除后排序策略。
- 删除策略的胜出次数不转移；保留策略继承原胜出次数并在新池重新归一化席位权重。
- 标的票数并列时按 `asset_id` 字符串升序破局。
- Top-K 大于等于当日获票标的数时保留全部标的，但仍保留该配置标签。
- 所有资金权重按入选标的票数重新归一化，并检查每个调仓日、N、投票方式和选择配置的权重和为 1。
